# Политика безопасности

## Поддерживаемые версии

Обновления безопасности выпускаются только для последней опубликованной версии
TMC StaffWork. Обновляйтесь до актуальной версии перед сообщением об уязвимости.

## Сообщить об уязвимости

**Не создавайте публичный Issue для уязвимостей.** Вместо этого напишите автору
напрямую через GitHub: [github.com/younaxo](https://github.com/younaxo/).
Опишите:

- версию плагина и платформу (Paper/Spigot/Folia), на которой воспроизводится проблема;
- тип хранилища (YAML/SQLite/H2/MySQL) и включена ли интеграция с Telegram;
- шаги для воспроизведения;
- потенциальное воздействие (какие данные/действия затронуты).

Постараемся подтвердить получение в течение нескольких дней и сообщить о
статусе исправления.

## Что уже сделано для безопасности

- Все SQL-запросы выполняются через `PreparedStatement` — без конкатенации
  пользовательского ввода в SQL.
- Пароли и токены (MySQL/MariaDB, Telegram bot-token) читаются только из
  локального `config.yml` на сервере и никогда не пишутся в лог.
- Код привязки Telegram-аккаунта хранится только в виде SHA-256 хеша и действует
  ограниченное время; попытки привязки ограничены по частоте (rate limit).
- Все команды проверяют permission на стороне сервера независимо от видимости
  команды в клиенте.
- Пользовательский ввод, попадающий в текст сообщений (например, введённое имя
  игрока), экранируется перед подстановкой в шаблон, чтобы не допустить
  внедрения разметки MiniMessage.
- Сетевые запросы (Telegram Bot API) и обращения к базе данных выполняются
  только в асинхронном потоке — никогда в основном/региональном потоке сервера.
- Идентификаторы рангов и другие настраиваемые значения нормализуются и
  проверяются регулярными выражениями перед использованием.

## Что не входит в область ответственности плагина

- Безопасность самого сервера Minecraft, операционной системы и сети.
- Безопасность стороннего ПО (PlaceholderAPI, СУБД MySQL/MariaDB, Telegram),
  используемого плагином как внешняя зависимость.
- Защита от скомпрометированного `config.yml`, к которому уже есть доступ на
  запись у злоумышленника (это равносильно полному доступу к серверу).
