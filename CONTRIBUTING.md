# Участие в разработке TMC StaffWork

Спасибо за интерес к проекту! Прежде чем предлагать изменения, ознакомьтесь с
[LICENSE.md](LICENSE.md) — распространение самостоятельно изменённых копий Плагина
запрещено. Ниже описано, как правильно сообщить об ошибке, предложить улучшение
или прислать патч так, чтобы он мог быть принят автором.

## Сообщить об ошибке

Откройте [Issue](https://github.com/younaxo/twomcsu-staffwork/issues) и укажите:

- версию плагина (`/staffwork version`);
- версию Minecraft/Paper/Spigot/Folia и версию Java;
- тип используемого хранилища (YAML/SQLite/H2/MySQL);
- шаги для воспроизведения проблемы;
- полный текст ошибки из лога сервера (`latest.log`), **без** токенов и паролей;
- ожидаемое и фактическое поведение.

## Предложить улучшение

Опишите в Issue задачу, которую улучшение решает, и предполагаемое поведение.
Не все предложения будут приняты — проект намеренно ограничивает объём версии 0.1
базовым набором функций, описанным в README.

## Присылать Pull Request

Присылая Pull Request в этот репозиторий, вы соглашаетесь, что ваш вклад
становится частью проекта на тех же условиях, что и [LICENSE.md](LICENSE.md), и
может быть принят, изменён или отклонён автором по его усмотрению. Это отличается
от независимого форка или распространения собственной изменённой версии Плагина,
что запрещено лицензией.

Перед отправкой PR:

1. Убедитесь, что `./gradlew build` проходит локально (сборка, тесты, Checkstyle,
   Spotless).
2. Не добавляйте в коммит секреты, токены, пароли, локальные конфигурации IDE
   или файлы сборки.
3. Пишите сообщения коммитов и описание PR на русском языке, по смыслу изменений.
4. Комментарии в коде — на русском или английском, только там, где они объясняют
   причину или нетривиальное ограничение, а не пересказывают очевидный код.
5. Технические идентификаторы (классы, методы, поля, ключи конфигурации) —
   на английском языке по общепринятым правилам Java.

## Стиль кода

- Java, package `su.twomc.staffwork`.
- Бизнес-логика (сервисы) не должна напрямую зависеть от Bukkit API, конкретного
  хранилища или Telegram API — используйте существующие интерфейсы и слои.
- Любое обращение к сети или базе данных — асинхронно, через
  `su.twomc.staffwork.scheduler.PlatformScheduler`.
- Новые permission-узлы — строго в формате `tmc.staffwork.<категория>...`
  (см. [`Permissions.java`](src/main/java/su/twomc/staffwork/command/Permissions.java)).

## Локальная сборка

```bash
./gradlew build
```

Собранный JAR появится в `build/libs/TMCStaffWork-<версия>.jar`.
