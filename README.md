# TMC StaffWork

Плагин управления персоналом и учёта рабочего времени для Minecraft-серверов.
Разработан для сети **twomc.su**, но подходит для любого сервера, которому
нужен учёт смен модераторов/администраторов, статусов и статистики.

## Возможности

- **Управление персоналом**: добавление/удаление сотрудников, внутренние ранги,
  включение/отключение, UUID как основной идентификатор, последний известный
  ник, дата и автор добавления.
- **Учёт рабочего времени**: статусы `WORKING`, `AFK`, `OFF_DUTY`, `BREAK`,
  `MEETING`, `TRAINING`; рабочие сессии (`/start`, `/stop`); статистика за
  сегодня/неделю/месяц/всё время; настраиваемый список статусов, засчитываемых
  как рабочее время.
- **Автоматизация статусов**: статус и старт сессии при входе, поведение при
  выходе, автоматический AFK по бездействию с возвратом в предыдущий статус.
- **Восстановление после сбоя**: если сервер завершился аварийно, при следующем
  запуске "зависшие" сессии корректно закрываются по последнему известному
  моменту, когда сервер был жив, а не по времени перезапуска.
- **Четыре хранилища данных**: YAML, SQLite (по умолчанию), H2,
  MySQL/MariaDB — через единый интерфейс, с собственной системой миграций схемы.
- **Гибкие permission**: формат `tmc.staffwork.<категория>...`, родительские
  группы `user`/`staff`/`moderator`/`admin`/`*`.
- **PlaceholderAPI** — мягкая зависимость, плагин работает и без неё.
- **Telegram** — отключаемая по умолчанию интеграция: привязка аккаунта по
  одноразовому коду, уведомления о входе/выходе и сменах.
- **Folia** — реальная поддержка через собственный слой планировщика (не только
  запись в `plugin.yml`).

## Совместимость

Чтобы не выдавать желаемое за действительное, совместимость разделена на три категории.

### Подтверждено сборкой и модульными тестами

- Компиляция и модульные тесты проходят на **Java 21** (используется в CI и при
  разработке).
- Хранилища **SQLite** и **H2** проверены модульными тестами (полный жизненный
  цикл: миграция схемы, CRUD, сессии, интервалы статусов).
- Хранилище **YAML** проверено модульными тестами, включая перезапись файла и
  чтение после "перезапуска".
- Бизнес-логика (расчёт времени, переходы статусов, восстановление после сбоя,
  привязка Telegram) проверена модульными тестами независимо от Bukkit.

### Архитектурно предполагается (спроектировано, но не прогонялось на живом сервере в CI)

- **Paper/Folia 1.20 – 1.21.11**: плагин компилируется против
  `io.papermc.paper:paper-api:1.20.6` (нижняя граница заявленного диапазона) —
  Paper API аддитивно обратно совместим, поэтому используемые методы должны
  быть доступны вплоть до 1.21.11. Планировщик Paper/Folia (`GlobalRegionScheduler`,
  `RegionScheduler`, `AsyncScheduler`, `EntityScheduler`) — часть Paper API,
  доступная как на Folia, так и на обычном Paper.
- **Обычный Spigot без Paper**: код не использует Paper-специфичный API, кроме
  явно изолированных мест (планировщик, определение Folia). Adventure/MiniMessage
  на таком сервере отсутствует на classpath — сообщения рендерятся через
  встроенный упрощённый legacy-конвертер (см. раздел «Форматирование сообщений»).
- **MySQL/MariaDB**: реализация написана и покрыта тем же общим SQL-слоем, что и
  SQLite/H2 (различие — только в диалекте), но не тестировалась в CI против
  живого сервера БД — требуется тестирование в конкретном окружении.
- **Java 17** (сервера 1.20–1.20.4): итоговый JAR собирается с
  `--release 17`, то есть байт-код совместим с Java 17 и Java 21 в одном файле.
  Реального запуска на JVM 17 в CI не выполнялось.

### Не тестировалось вовсе

- Minecraft 1.21.11 как таковой не тестировался вживую (на момент разработки
  это последняя опубликованная версия ветки 1.21.x в репозитории PaperMC).
- PaperSpigot/UniversalSpigot как отдельные ядра — рассматриваются как
  совместимые со Spigot API форки без отдельного тестирования; отдельного
  публичного API у них нет.
- Многосерверная сеть с общей MySQL/MariaDB базой (`server-id`) — реализована
  архитектурно (сессии и статистика помечаются идентификатором сервера), но не
  проверялась на реальной сети из нескольких серверов.

## Требования

- **Java 17** — для Minecraft 1.20–1.20.4.
- **Java 21** — для более новых версий (рекомендуется в целом).
- Paper, Folia, либо совместимое со Spigot API ядро.
- (Опционально) PlaceholderAPI 2.11+.
- (Опционально) сервер MySQL/MariaDB, если выбрано соответствующее хранилище.

## Установка

1. Скачайте `TMCStaffWork-<версия>.jar` из
   [GitHub Releases](https://github.com/younaxo/twomcsu-staffwork/releases) или
   соберите из исходников (см. ниже).
2. Поместите файл в папку `plugins/` сервера.
3. Перезапустите сервер.
4. Плагин создаст `plugins/TMCStaffWork/config.yml`, `messages_ru.yml`,
   `ranks.yml` и файл данных выбранного хранилища.

## Первый запуск

1. Выдайте себе право `tmc.staffwork.admin.*` (по умолчанию есть у операторов).
2. Добавьте первого сотрудника: `/staffwork add <ник> [ранг]`.
3. Проверьте настройки в `config.yml` (часовой пояс, хранилище, статусы,
   автоматизация) и выполните `/staffwork reload`.
4. Сотрудник может начать смену: `/staffwork start`, менять статус —
   `/staffwork status <статус>`, посмотреть статистику — `/staffwork stats`.

## Команды

Корневая команда — `/staffwork`, короткий алиас — `/sw`.

| Команда | Описание |
|---|---|
| `/staffwork help` | Справка по командам |
| `/staffwork info [игрок]` | Карточка сотрудника |
| `/staffwork list` | Список сотрудников |
| `/staffwork add <игрок> [ранг]` | Добавить сотрудника |
| `/staffwork remove <игрок>` | Удалить сотрудника |
| `/staffwork rank set <игрок> <ранг>` | Назначить ранг |
| `/staffwork status [статус]` | Посмотреть/сменить свой статус |
| `/staffwork status set <игрок> <статус>` | Сменить статус другого сотрудника |
| `/staffwork start` / `/staffwork stop` | Начать/завершить рабочую сессию |
| `/staffwork stats [игрок] [today\|week\|month\|all]` | Статистика рабочего времени |
| `/staffwork telegram link` / `telegram unlink` | Привязать/отвязать Telegram |
| `/staffwork reload` | Перезагрузить конфигурацию |
| `/staffwork version` | Версия плагина |

Все подкоманды проверяют permission на стороне сервера независимо от того,
видна ли команда в клиенте (tab-completion не является защитой).

## Права доступа (permissions)

Формат: `tmc.staffwork.<категория>.<подкатегория>.<функция>`. Полный список — в
[`plugin.yml`](src/main/resources/plugin.yml). Родительские группы:

- `tmc.staffwork.user.*` (по умолчанию: у всех) — свой профиль, статус, сессия, статистика, Telegram.
- `tmc.staffwork.staff.*` (по умолчанию: выключено) — список сотрудников, просмотр чужих карточек.
- `tmc.staffwork.moderator.*` (по умолчанию: выключено) — изменение статуса/сессий/ранга других.
- `tmc.staffwork.admin.*` (по умолчанию: у операторов) — добавление/удаление сотрудников, reload.
- `tmc.staffwork.*` (по умолчанию: у операторов) — все права.

Опасные административные права **не** выдаются обычным игрокам по умолчанию.

## Настройка хранилища

В `config.yml`, раздел `storage.type`: `yaml`, `sqlite` (по умолчанию), `h2`
или `mysql`. **Изменение типа хранилища требует полного перезапуска сервера** —
`/staffwork reload` его не применит и явно предупредит об этом.

### Пример MySQL/MariaDB

```yaml
storage:
  type: mysql
  mysql:
    host: "127.0.0.1"
    port: 3306
    database: "tmc_staffwork"
    username: "tmc_staffwork"
    password: "надёжный-пароль-только-в-этом-файле"
    use-ssl: false
    pool-size: 10
```

Для сети из нескольких серверов на общей базе задайте разный `server-id`
(только латиница, цифры, `-`, `_`) на каждом сервере — сессии и heartbeat
помечаются им, поэтому серверы не будут закрывать активные сессии друг друга.

## PlaceholderAPI

Идентификатор расширения — `tmcstaff` (без точки — PlaceholderAPI не допускает
точки в идентификаторах, поэтому ранее предлагавшийся формат `%tmc.staff_...%`
невозможен и не заявляется рабочим).

| Плейсхолдер | Значение |
|---|---|
| `%tmcstaff_staff_status%` | Текущий статус (`WORKING`, `AFK`, ...) |
| `%tmcstaff_staff_status_color%` | Legacy-код цвета статуса (например, `§a`) |
| `%tmcstaff_staff_status_color_minimessage%` | Тег MiniMessage цвета (например, `<green>`) |
| `%tmcstaff_staff_is_working%` | `true`/`false` |
| `%tmcstaff_staff_work_time_today%` | Рабочее время за сегодня |
| `%tmcstaff_staff_work_time_week%` | За текущую неделю |
| `%tmcstaff_staff_work_time_month%` | За текущий месяц |
| `%tmcstaff_staff_total_work_time%` | За всё время |
| `%tmcstaff_staff_current_session_time%` | Длительность текущей сессии |

Значения обновляются раз в ~15 секунд из кэша (не при каждом запросе) — прямые
обращения к базе данных синхронно из PlaceholderAPI недопустимы.

## Telegram

Выключена по умолчанию. Токен бота храните только в `config.yml` на сервере —
**никогда не коммитьте его в Git**.

```yaml
telegram:
  enabled: true
  bot-token: "ваш-токен-от-@BotFather"
```

Игрок привязывает аккаунт командой `/staffwork telegram link` — плагин выдаёт
одноразовый код (действует 5 минут по умолчанию), который нужно отправить боту
в личные сообщения. В хранилище попадает только SHA-256 хеш кода. Интеграция
использует long polling (без открытия входящего порта) и не блокирует
серверные потоки.

## Конфигурация статусов и автоматизации

```yaml
work-time:
  counted-statuses: [WORKING, MEETING, TRAINING]

auto-status:
  status-on-join: "WORKING"
  auto-start-session-on-join: true
  on-quit: "stop-session"   # stop-session | set-status | nothing
  afk:
    enabled: true
    threshold-seconds: 300
    auto-return: true
```

## Форматирование сообщений

`messages_ru.yml` использует разметку [MiniMessage](https://docs.advntr.dev/minimessage/format.html).
На Paper/Folia сообщения рендерятся полноценно (цвета, `<bold>`, и т.д.). На
обычном Spigot без Paper (где нет Adventure на classpath) используется
встроенный упрощённый конвертер: поддерживаются именованные цвета и базовые
стили (`bold`, `italic`, `underlined`, `strikethrough`, `obfuscated`), но
закрывающий тег сбрасывает форматирование целиком, а не только его — для
полноценного вложенного форматирования нужен Paper.

## Резервное копирование

- **YAML**: копируйте `plugins/TMCStaffWork/data.yml`. Запись атомарна (через
  временный файл), но резервная копия перед обновлением плагина всё равно
  рекомендуется.
- **SQLite/H2**: копируйте файл(ы) базы данных при остановленном сервере
  (или с помощью штатных средств резервного копирования, поддерживающих
  консистентный снимок файла).
- **MySQL/MariaDB**: используйте штатные средства СУБД (`mysqldump` и т.п.).

Перед первым запуском новой версии плагина, меняющей схему БД, рекомендуется
сделать резервную копию — версия 0.1 является первой, миграции с более ранних
версий отсутствуют.

## Обновление

1. Сделайте резервную копию данных (см. выше).
2. Замените JAR-файл в `plugins/`.
3. Перезапустите сервер (не используйте `/reload` Bukkit).
4. Проверьте `plugins/TMCStaffWork/config.yml` — новые ключи добавляются
   автоматически со значениями по умолчанию, `config-version` обновляется.

## Сборка из исходников

Требуется JDK 21 (сборка использует toolchain Gradle, компиляция производится с
`--release 17` для совместимости итогового байт-кода).

```bash
git clone https://github.com/younaxo/twomcsu-staffwork.git
cd twomcsu-staffwork
./gradlew build
```

Собранный JAR: `build/libs/TMCStaffWork-<версия>.jar`.

Полезные задачи Gradle:

```bash
./gradlew test              # модульные тесты
./gradlew spotlessCheck     # проверка форматирования
./gradlew spotlessApply     # автоформатирование
./gradlew checkstyleMain    # статический анализ
```

## Известные ограничения версии 0.1

- MySQL/MariaDB реализованы, но не проверены против живого сервера БД в CI.
- Полноценное end-to-end тестирование на реальном запущенном сервере
  Paper/Spigot/Folia (а не только модульные тесты бизнес-логики) не входит в
  версию 0.1 — интеграционные тесты уровня MockBukkit/полноценного сервера
  запланированы на будущие версии.
- Legacy-фолбэк форматирования сообщений (для Spigot без Paper) поддерживает
  подмножество тегов MiniMessage без вложенного стека стилей.
- AFK-детект основан на стандартных событиях Bukkit (движение, чат, команды,
  взаимодействие) с троттлингом — не является идеально точным по секундам.
- `body_path` GitHub Release использует весь `CHANGELOG.md` целиком, а не
  выдержку по версии.
